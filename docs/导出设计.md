# MixedEditing 导出设计 — 时间线合成与 MP4 渲染

> 适用范围：剪辑工作区「导出」功能的设计与实现。
> 产物：单个 MP4 文件（H.264 视频 + AAC 音频）。
> 核心约束：**与主线程预览完全隔离**、**分段并行编码**、**可取消**、**进度可观测**。
> 实现位置：`src/ffmpeg/source/Exporter.cpp`、`src/ffmpeg/include/Exporter.h`，由 `EditorWindow::exportProject()` 调度。

---

## 1. 总体流程

```
┌──────────────────────────────────────────────────────────────────────┐
│ EditorWindow::exportProject()  (主线程)                                │
│  1. 校验序列非空 → 选输出路径(.mp4)                                     │
│  2. 从数据库快照 tracks / clipsByTrack / assetPathByClip → Request      │
│  3. 起 QThread + Exporter(moveToThread)，弹模态 QProgressDialog         │
└───────────────────────────────┬──────────────────────────────────────┘
                                 │ started → run()
┌────────────────────────────────▼─────────────────────────────────────┐
│ Exporter::run()  (worker 线程，不再访问数据库)                         │
│                                                                        │
│  阶段A 音频预混 mixAudio()         ── 进度 0%（通常很快）               │
│    所有 audio 轨片段 → seek/解码/重采样 48k 立体声 float                │
│    按时间线样本下标叠加进整轨缓冲 → 软限幅                              │
│                                                                        │
│  阶段B 视频分段并行 encodeSegment() ── 进度 0~85%                       │
│    [0,totalFrames) 切成 poolSize 个连续帧区间                          │
│    每段 std::async：自带 CompositionEngine 顺序合成→H.264→临时 MP4      │
│    framesDone 原子计数，主线程 80ms 轮询汇报                            │
│                                                                        │
│  阶段C 最终封装                     ── 进度 85~100%                     │
│    AAC 整体编码为内存包                                                 │
│    按段顺序读视频包 → 重写全局递增 pts/dts → stream-copy 拼接           │
│    手动按时间交错写入音频包 → write_trailer                            │
└────────────────────────────────────────────────────────────────────────┘
```

进度切分：音频 `0%` 起跑 → 视频编码 `0~85%` → 封装拼接 `85~98%` → 完成 `100%`。

## 2. 线程模型与生命周期

导出是一个 `QObject` worker，通过 `moveToThread` 跑在独立 `QThread` 上，由 `EditorWindow` 调度：

- **主线程快照**：起线程前把 `tracks` / `clipsByTrack`（track.id → clips）/ `assetPathByClip`（clip.id → 源文件路径）全部读出装入 `Exporter::Request`。worker 运行期间**不访问数据库**，规避 SQLite 跨线程连接与锁竞争。
- **信号接线**：
  - `QThread::started → Exporter::run`
  - `Exporter::progress(int) → QProgressDialog::setValue`
  - `QProgressDialog::canceled → Exporter::cancel`（直连，跨线程置原子标志）
  - `Exporter::finished(bool,QString) →` 主线程清理线程、复位 `m_exporting`、提示结果
- **单任务约束**：`m_exporting` 保证同时只有一个导出任务。
- **取消**：`cancel()` 仅设置 `std::atomic<bool> m_cancelled`，worker 在各阶段检查点轮询；`EditorWindow` 关闭时也会 `cancel()` + `quit()/wait()` join 线程，防止悬挂。

`Exporter` 自带独立的 `CompositionEngine` 与解码器，**不与主线程预览共享任何对象**，因此线程安全。

## 3. 阶段 A：音频预混（mixAudio）

把所有音频轨的所有片段混成**一条覆盖整个时长的交错 float 立体声缓冲**：

```
totalSamples = ceil(durationUs / 1e6 * 48000)
mix[totalSamples * 2]  全部初始化为 0

对每个 audio 轨的每个片段：
  open → find_stream_info → 找音频流 → 开解码器
  swr 重采样目标：48000Hz / 立体声 / AV_SAMPLE_FMT_FLT（交错）
  av_seek_frame 到 clip.sourceInUs（BACKWARD）→ flush
  循环解码：
    帧 pts ≥ clip.sourceOutUs → 停止
    样本起点 = round((clip.timelineStartUs + (framePtsUs - sourceInUs)) / 1e6 * 48000)
    mix[dst] += sample   ← 叠加混音（多轨/重叠相加）
最后：每个采样 clamp(-1, 1)  ← 软限幅防溢出
```

**设计取舍**：

- 用「整轨内存缓冲 + 相加」换实现简单，天然支持多轨与片段重叠。
- 代价是内存随时长线性增长（48k×2ch×4B ≈ **384 KB/秒**，一小时约 1.3 GB），超长工程内存压力大。
- 限幅为硬 `clamp` 而非动态压缩，重叠密集时可能削顶失真。
- 当前未应用 `clip.volume` / `track.volume` 增益（后续可在叠加前乘系数）。

## 4. 阶段 B：视频分段并行编码（encodeSegment）

这是导出性能的核心。把整个帧区间 `[0, totalFrames)` 切成若干**连续帧区间**，每段独立编码到 `QTemporaryDir` 下的临时 MP4（`seg_k.mp4`），用 `std::async(std::launch::async)` 并行起 worker。

### 4.1 编码器选择（pickH264Encoder）

```
优先 h264_videotoolbox (macOS 硬件)：
  alloc 一个 probe ctx → 设参数 → 真正 avcodec_open2 试开
  试开成功 → 用硬件；失败 → 回退 libx264
```

用「试开探测」而非仅检查 codec 是否存在，避免分段跑到一半某段才发现硬件不可用。

### 4.2 并行度决策

```
cores = hardware_concurrency()（取不到按 4）
硬件编码：poolSize = clamp(cores, 1, 8)        ← 硬件会话省 CPU，可多分段
软件编码：poolSize = clamp(cores/2, 1, 4)      ← libx264 段内已多线程，少分段防过度订阅
帧数太少：poolSize = min(poolSize, totalFrames/30)   ← 短片不白起线程
软件编码每段线程数 perThreads = cores / segs.size()
```

### 4.3 单段编码（encodeSegment）

- 自带 `CompositionEngine`，**仅在区间起点 seek 一次**，其后顺序解码——契合视频解码的顺序访问特性。
- 编码器配置关键项：
  - `pix_fmt = YUV420P`，`bit_rate = 6 Mbps`，`gop_size = FPS`
  - **`max_b_frames = 0`**：无 B 帧 → `pts == dts`，封装拼接时无需处理重排序
  - 软件编码：`preset=veryfast` + `tune=fastdecode`
  - 硬件编码：`realtime=1` + `allow_sw=1`（不可用时允许软回退）
- 逐帧：`composeAt(i * 1e6 / FPS)` → `fillVideoFrame` 拷进 AVFrame → 编码。**段内本地 pts 从 0 起算**（`i - startFrame`）。
- `fillVideoFrame` 对尺寸不符或无效帧直接填黑场（Y=16, U/V=128）；正常情况 `CompositionEngine` 已把所有片段合成到画布尺寸。
- 每完成一帧 `framesDone.fetch_add(1)`，主线程据此汇报 0~85% 进度。

## 5. 阶段 C：最终封装（拼接 + 交错）

各段编码完成后，主流程把它们拼成一个最终 MP4：

### 5.1 视频拼接（stream-copy）

- 视频输出流参数从**第一段** `avcodec_parameters_copy` 拿取（含 SPS/PPS extradata），`codec_tag = 0`。
- 按段顺序读取各段视频包，**重写为全局递增 pts/dts**：`pkt->pts = pkt->dts = av_rescale_q(gf, {1,FPS}, time_base)`，`gf` 为全局帧序号。因无 B 帧，pts==dts，拼接无缝。
- 不重编码，stream-copy 直接写入，拼接阶段几乎零成本。

### 5.2 音频编码与交错

- 音频整体编码为内存中的 AAC 包（`AV_CODEC_ID_AAC`，`FLTP`，48k 立体声，192 kbps）。AAC 包很小，全放内存便于按时间交错。
- **手动交错**：每写一个视频帧前，把所有 `tSec ≤ 当前视频帧时间` 的音频包先写出，保证送入 muxer 的时间戳单调，再 `av_interleaved_write_frame`。
- 视频写完后冲洗剩余音频包；出错/取消时回收所有未写出的音频包，避免内存泄漏。

### 5.3 收尾

- 成功：`av_write_trailer` → `progress(100)` → `finished(true, outputPath)`。
- 取消/失败：`QFile::remove(outputPath)` 删半成品 → `finished(false, 原因)`。

---

## 6. 设计亮点

- **分段并行 + 无重编码拼接**：并行编码缩短墙钟时间，「无 B 帧 + 全局 pts 重写 + stream-copy」让拼接近乎零成本。
- **硬件优先 + 试开探测 + 软回退**：跨设备健壮。
- **无锁进度**：原子计数 + 80ms 轮询，跨线程零锁。
- **快照式数据隔离**：worker 不碰数据库，彻底规避线程安全问题。
- **完整的取消/错误/临时文件清理路径**。

## 7. 已知限制与改进方向

| 限制 | 说明 | 可能的改进 |
| --- | --- | --- |
| 音频全内存 | 整轨 float 缓冲随时长线性增长，长片吃内存 | 分块流式混音 / 写临时 WAV |
| 音频串行预混 | 单线程顺序处理所有音频片段 | 按片段并行解码后归并 |
| 硬限幅失真 | 重叠密集时 clamp 削顶 | 动态范围压缩 / 归一化 |
| 未应用音量增益 | `clip.volume` / `track.volume` 未参与混音 | 叠加前乘增益系数 |
| 仅 MP4/H.264/AAC | 输出格式固定 | 暴露 `ExportJob` 中的 codec/格式选项 |
| 特效/转场未参与 | 合成引擎特效链仍为占位 | 待 CompositionEngine 阶段推进后自动生效 |
