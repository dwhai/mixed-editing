# MixedEditing 视频剪辑后端 — 数据库设计

> 适用范围：Qt6 桌面端视频剪辑功能的持久化层。
> 架构形态：**本地 SQLite 优先 + 云端 MySQL 同步**，支持**多用户**与**多轨时间线剪辑**。
> 单位约定：所有时间字段统一为 **INTEGER 微秒**（后缀 `_us`），时间戳为 **unix 毫秒**。

---

## 1. 总体架构

```
┌─────────────────────────┐         同步协议 (HTTPS/JSON)        ┌──────────────────────────┐
│   PC 端 (Qt6 + SQLite)  │  ◄──────────────────────────────►  │   服务端 (REST + MySQL)   │
│                         │     增量推送 oplog / 拉取变更        │                          │
│  - 离线可用，本地权威    │                                      │  - 多设备汇聚，云端权威   │
│  - 工程/素材/时间线      │                                      │  - 鉴权/账户/工程归属      │
│  - 渲染导出执行          │                                      │  - 冲突仲裁/历史版本       │
└─────────────────────────┘                                      └──────────────────────────┘
```

两端 schema **结构对齐、类型适配**：

- PC 端为单机离线设计，主键用 UUID，软删除 + oplog 驱动同步。
- 服务端为多用户多设备设计，增加鉴权、归属隔离、服务端权威时间与版本仲裁。

---

## 2. 核心设计原则

1. **UUID 主键（非自增）**：多设备离线各自生成记录，自增整数必然冲突。两端主键均为 `CHAR(36)` / `TEXT` UUID。
2. **同步四件套**：每张可同步表都带 `created_at` / `updated_at`（unix 毫秒）、`deleted_at`（软删除）、`rev`（修订号）。
3. **微秒整数计时**：帧级精度，避免浮点累积误差，跨帧率通用。`PlayerTypes` 中以秒为单位的 `pts` 转换只需 ÷1e6。
4. **结构化关系建表，可变参数用 JSON**：轨道→片段→关键帧建独立表；特效参数、变换、动画曲线用 JSON 列（SQLite `json1` / MySQL `JSON`）。
5. **oplog 驱动增量同步**：不做整库 diff，本地每次写操作记一条变更日志。
6. **软删除不物理删**：删除写 `deleted_at` 并产生 delete oplog，否则删除无法跨设备传播。

---

## 3. 实体关系总览

```
account (用户)
  └── project (剪辑工程)            settings: 分辨率/帧率/采样率
        ├── media_asset (素材库)     本地文件 / 开眼远程 / 云端
        └── sequence (时间线/序列)
              └── track (轨道: video/audio/text)
                    ├── clip (片段: 引用素材 + trim + 时间线位置)
                    │     ├── effect (滤镜/特效, 参数 JSON)
                    │     ├── keyframe (关键帧动画)
                    │     └── text_element (文字/字幕内容)
                    └── transition (相邻两片段间转场)
        └── export_job (导出/渲染任务，本地执行)

[同步基础设施] device / sync_oplog (PC端)  ·  device / sync_change (服务端)
```

## 4. PC 端 — SQLite 设计

启用约束与 JSON：

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;   -- 读写并发，剪辑预览与写入并行
```

### 4.1 账户与工程

```sql
-- 用户账户（本地缓存，云端权威）
CREATE TABLE account (
    id              TEXT PRIMARY KEY,            -- UUID
    username        TEXT NOT NULL,
    email           TEXT,
    avatar_url      TEXT,
    auth_token      TEXT,                        -- 当前设备会话令牌（不存密码）
    token_expire_at INTEGER,
    created_at      INTEGER NOT NULL,
    updated_at      INTEGER NOT NULL,
    deleted_at      INTEGER,
    rev             INTEGER NOT NULL DEFAULT 1
);

-- 剪辑工程
CREATE TABLE project (
    id           TEXT PRIMARY KEY,
    account_id   TEXT NOT NULL REFERENCES account(id),
    title        TEXT NOT NULL DEFAULT '未命名工程',
    description  TEXT,
    cover_path   TEXT,                           -- 工程缩略图本地路径
    width        INTEGER NOT NULL DEFAULT 1920,
    height       INTEGER NOT NULL DEFAULT 1080,
    fps          REAL    NOT NULL DEFAULT 30.0,
    sample_rate  INTEGER NOT NULL DEFAULT 48000,
    duration_us  INTEGER NOT NULL DEFAULT 0,     -- 缓存总时长
    settings     TEXT,                           -- JSON: 颜色空间/背景色等
    created_at   INTEGER NOT NULL,
    updated_at   INTEGER NOT NULL,
    deleted_at   INTEGER,
    rev          INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_project_account ON project(account_id) WHERE deleted_at IS NULL;
```

### 4.2 素材库

```sql
-- 媒体素材：本地文件 / 开眼远程 / 云端
CREATE TABLE media_asset (
    id              TEXT PRIMARY KEY,
    project_id      TEXT NOT NULL REFERENCES project(id),
    media_type      TEXT NOT NULL CHECK (media_type IN ('video','audio','image')),
    source_kind     TEXT NOT NULL CHECK (source_kind IN ('local','kaiyan','cloud')),

    -- 来源定位（按 source_kind 有效其一）
    file_path       TEXT,                        -- local 绝对路径
    remote_url      TEXT,                        -- kaiyan/cloud 播放或下载地址
    kaiyan_video_id INTEGER,                      -- 关联开眼 VideoData.id

    -- 探测元信息
    display_name    TEXT NOT NULL,
    duration_us     INTEGER NOT NULL DEFAULT 0,
    width           INTEGER,
    height          INTEGER,
    fps             REAL,
    sample_rate     INTEGER,
    channels        INTEGER,
    codec           TEXT,
    file_size       INTEGER,
    checksum        TEXT,                         -- 内容哈希：去重 + 同步比对

    -- 剪辑加速资源
    thumbnail_path  TEXT,                         -- 首帧缩略图
    proxy_path      TEXT,                         -- 低清代理
    waveform_path   TEXT,                         -- 音频波形缓存

    created_at      INTEGER NOT NULL,
    updated_at      INTEGER NOT NULL,
    deleted_at      INTEGER,
    rev             INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_asset_project  ON media_asset(project_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_asset_checksum ON media_asset(checksum);
```

### 4.3 时间线：序列 / 轨道 / 片段

```sql
-- 序列（一个工程可有多条时间线，主时间线 is_main=1）
CREATE TABLE sequence (
    id           TEXT PRIMARY KEY,
    project_id   TEXT NOT NULL REFERENCES project(id),
    name         TEXT NOT NULL DEFAULT '时间线 1',
    is_main      INTEGER NOT NULL DEFAULT 1,
    duration_us  INTEGER NOT NULL DEFAULT 0,
    created_at   INTEGER NOT NULL,
    updated_at   INTEGER NOT NULL,
    deleted_at   INTEGER,
    rev          INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_sequence_project ON sequence(project_id) WHERE deleted_at IS NULL;

-- 轨道（track_index 越大越靠上 / 越先合成）
CREATE TABLE track (
    id           TEXT PRIMARY KEY,
    sequence_id  TEXT NOT NULL REFERENCES sequence(id),
    track_type   TEXT NOT NULL CHECK (track_type IN ('video','audio','text')),
    track_index  INTEGER NOT NULL,
    name         TEXT,
    is_muted     INTEGER NOT NULL DEFAULT 0,
    is_locked    INTEGER NOT NULL DEFAULT 0,
    is_hidden    INTEGER NOT NULL DEFAULT 0,
    volume       REAL    NOT NULL DEFAULT 1.0,
    created_at   INTEGER NOT NULL,
    updated_at   INTEGER NOT NULL,
    deleted_at   INTEGER,
    rev          INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_track_sequence ON track(sequence_id) WHERE deleted_at IS NULL;

-- 片段：放在轨道上的素材实例
CREATE TABLE clip (
    id                TEXT PRIMARY KEY,
    track_id          TEXT NOT NULL REFERENCES track(id),
    asset_id          TEXT REFERENCES media_asset(id),   -- text 片段可 NULL
    kind              TEXT NOT NULL CHECK (kind IN ('video','audio','image','text')),

    timeline_start_us INTEGER NOT NULL,                  -- 在序列中的起点
    duration_us       INTEGER NOT NULL,
    source_in_us      INTEGER NOT NULL DEFAULT 0,        -- 源裁剪入点
    source_out_us     INTEGER NOT NULL DEFAULT 0,        -- 源裁剪出点

    speed             REAL NOT NULL DEFAULT 1.0,         -- 变速
    opacity           REAL NOT NULL DEFAULT 1.0,
    volume            REAL NOT NULL DEFAULT 1.0,
    transform         TEXT,                              -- JSON: 位置/缩放/旋转/裁切
    is_enabled        INTEGER NOT NULL DEFAULT 1,

    created_at        INTEGER NOT NULL,
    updated_at        INTEGER NOT NULL,
    deleted_at        INTEGER,
    rev               INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_clip_track ON clip(track_id, timeline_start_us) WHERE deleted_at IS NULL;
CREATE INDEX idx_clip_asset ON clip(asset_id);
```

### 4.4 特效 / 转场 / 关键帧 / 文字

```sql
-- 特效/滤镜：挂在 clip 或 track 上
CREATE TABLE effect (
    id           TEXT PRIMARY KEY,
    owner_type   TEXT NOT NULL CHECK (owner_type IN ('clip','track')),
    owner_id     TEXT NOT NULL,                  -- clip.id 或 track.id
    effect_type  TEXT NOT NULL,                  -- 'blur'/'lut'/'chroma_key'/'eq'...
    order_index  INTEGER NOT NULL DEFAULT 0,     -- 特效链顺序
    is_enabled   INTEGER NOT NULL DEFAULT 1,
    params       TEXT,                           -- JSON
    created_at   INTEGER NOT NULL,
    updated_at   INTEGER NOT NULL,
    deleted_at   INTEGER,
    rev          INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_effect_owner ON effect(owner_type, owner_id) WHERE deleted_at IS NULL;

-- 转场：同轨相邻两片段之间
CREATE TABLE transition (
    id              TEXT PRIMARY KEY,
    track_id        TEXT NOT NULL REFERENCES track(id),
    from_clip_id    TEXT REFERENCES clip(id),    -- 片段开头可 NULL
    to_clip_id      TEXT REFERENCES clip(id),    -- 片段结尾可 NULL
    transition_type TEXT NOT NULL,               -- 'fade'/'dissolve'/'wipe'...
    duration_us     INTEGER NOT NULL,
    params          TEXT,
    created_at      INTEGER NOT NULL,
    updated_at      INTEGER NOT NULL,
    deleted_at      INTEGER,
    rev             INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_transition_track ON transition(track_id) WHERE deleted_at IS NULL;

-- 关键帧：对 clip 或 effect 的某属性做动画
CREATE TABLE keyframe (
    id             TEXT PRIMARY KEY,
    owner_type     TEXT NOT NULL CHECK (owner_type IN ('clip','effect')),
    owner_id       TEXT NOT NULL,
    property_name  TEXT NOT NULL,                -- 'opacity'/'scale'/'blur.radius'...
    time_offset_us INTEGER NOT NULL,             -- 相对 clip 起点
    value          TEXT NOT NULL,                -- JSON: 标量或向量
    interpolation  TEXT NOT NULL DEFAULT 'linear', -- linear/bezier/hold
    bezier_handles TEXT,                          -- JSON: 贝塞尔控制点
    created_at     INTEGER NOT NULL,
    updated_at     INTEGER NOT NULL,
    deleted_at     INTEGER,
    rev            INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_keyframe_owner
    ON keyframe(owner_type, owner_id, property_name, time_offset_us)
    WHERE deleted_at IS NULL;

-- 文字/字幕内容（kind='text' 的 clip 关联）
CREATE TABLE text_element (
    clip_id     TEXT PRIMARY KEY REFERENCES clip(id),
    content     TEXT NOT NULL,
    font_family TEXT,
    font_size   REAL,
    color       TEXT,                            -- '#RRGGBBAA'
    alignment   TEXT,                            -- left/center/right
    style       TEXT,                            -- JSON: 粗体/描边/阴影/背景
    updated_at  INTEGER NOT NULL,
    rev         INTEGER NOT NULL DEFAULT 1
);
```

## 5. 服务端 — MySQL 设计

引擎与字符集统一：`ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`。

与 PC 端差异说明：

- 主键 `CHAR(36)`（UUID），与客户端一致，便于直接落库。
- 时间字段用 `BIGINT`（unix 毫秒 / 微秒），不用 MySQL `DATETIME`，保证两端语义一致、无时区歧义。
- 增加**鉴权字段**（密码哈希、盐）与**工程归属隔离**（所有查询按 `account_id` 过滤）。
- 增加**服务端权威版本**：`server_rev` 全局递增，作为增量同步游标；客户端 `rev` 仅作冲突仲裁参考。
- JSON 可变参数用原生 `JSON` 类型。

### 5.1 账户与认证

```sql
CREATE TABLE account (
    id              CHAR(36)     NOT NULL,
    username        VARCHAR(64)  NOT NULL,
    email           VARCHAR(255) NOT NULL,
    password_hash   VARCHAR(255) NOT NULL,        -- bcrypt/argon2
    avatar_url      VARCHAR(512),
    status          TINYINT      NOT NULL DEFAULT 1,  -- 1 正常 0 禁用
    created_at      BIGINT       NOT NULL,
    updated_at      BIGINT       NOT NULL,
    deleted_at      BIGINT       NULL,
    rev             INT          NOT NULL DEFAULT 1,
    PRIMARY KEY (id),
    UNIQUE KEY uk_account_email    (email),
    UNIQUE KEY uk_account_username (username)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 会话令牌（支持多设备登录、单独吊销）
CREATE TABLE auth_token (
    id            CHAR(36)     NOT NULL,
    account_id    CHAR(36)     NOT NULL,
    device_id     CHAR(36)     NOT NULL,
    access_token  VARCHAR(512) NOT NULL,
    refresh_token VARCHAR(512) NOT NULL,
    expire_at     BIGINT       NOT NULL,
    created_at    BIGINT       NOT NULL,
    revoked       TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (id),
    UNIQUE KEY uk_token_access (access_token),
    KEY idx_token_account (account_id),
    CONSTRAINT fk_token_account FOREIGN KEY (account_id) REFERENCES account(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 登录设备
CREATE TABLE device (
    id           CHAR(36)    NOT NULL,
    account_id   CHAR(36)    NOT NULL,
    device_name  VARCHAR(128),
    platform     VARCHAR(32),
    last_sync_rev BIGINT     NOT NULL DEFAULT 0,  -- 该设备已同步到的 server_rev
    last_sync_at BIGINT,
    created_at   BIGINT      NOT NULL,
    PRIMARY KEY (id),
    KEY idx_device_account (account_id),
    CONSTRAINT fk_device_account FOREIGN KEY (account_id) REFERENCES account(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## 6. 云同步策略

### 6.1 同步流程

**推送（PC → 云）**

1. 客户端取 `sync_oplog WHERE synced=0 ORDER BY id`，批量 `POST /sync/push`。
2. 服务端在一个事务内：对每条变更按 `row_id` UPSERT 到对应业务表 → 从 `server_rev_seq` 取新版本号写入该行 `server_rev` → 追加一条 `sync_change`。
3. 返回成功后，客户端把这批 oplog 置 `synced=1`。

**拉取（云 → PC）**

1. 客户端用 `device.last_sync_at`（PC 端）/ 服务端 `device.last_sync_rev` 作游标，`GET /sync/pull?since=<server_rev>`。
2. 服务端查 `sync_change WHERE account_id=? AND server_rev > ? ORDER BY server_rev`，回各行最新快照（排除 `origin_device` 为本设备的，避免回声）。
3. 客户端逐行按 LWW 合并入本地表，并推进游标。

### 6.2 冲突解决

- 默认 **行级 Last-Write-Wins**：比较 `updated_at`，新者胜；同毫秒比 `rev`。
- 删除用软删除传播：`deleted_at` 非空即删除态，永不物理删；后台 GC 在同步确认 30 天后物理清理。
- 高频结构表（`clip` / `keyframe`）若后续需要更细的合并粒度，可升级为字段级合并或 CRDT；首版 LWW 足够且复杂度最低。

### 6.3 两端游标对照

| 角色 | 增量推送依据 | 增量拉取游标 |
|------|--------------|--------------|
| PC 端 | `sync_oplog.synced=0` | `device.last_sync_at` → 服务端按 `server_rev` 返回 |
| 服务端 | 写业务表时追加 `sync_change` | `sync_change.server_rev > device.last_sync_rev` |

## 7. 两端字段类型对照

| 语义 | PC 端 SQLite | 服务端 MySQL | 说明 |
|------|--------------|--------------|------|
| 主键 | `TEXT` (UUID) | `CHAR(36)` | 客户端离线生成，全局唯一 |
| 时间戳 | `INTEGER` (ms) | `BIGINT` (ms) | unix 毫秒，无时区歧义 |
| 时长/位置 | `INTEGER` (µs) | `BIGINT` (µs) | 帧级精度 |
| 浮点 | `REAL` | `DOUBLE` | fps/音量/不透明度 |
| 布尔 | `INTEGER` 0/1 | `TINYINT` 0/1 | |
| 枚举 | `TEXT` + `CHECK` | `ENUM(...)` | |
| 可变参数 | `TEXT` (json1) | `JSON` | 特效/变换/动画曲线 |
| 软删除 | `deleted_at` | `deleted_at` | NULL=存活 |
| 修订号 | `rev` | `rev` + `server_rev` | 服务端多一个全局版本 |
